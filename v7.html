SECTION 01

삼성SDI 후공정 벤치마킹 & Factory I/O HIL(가상 계측) 구현 원칙

DOMAIN & HIL ARCHITECTURE

전해액 주입 직후 베어 셀 화학 활성화(초기 충방전·디게싱)는 Project C의 팩 조립 범위와 맞지 않으므로 제외하고, 4S·6S 팩을 단위로 조립 후 시간 경과에 따른 자기방전(ΔV)·접점 접촉저항(AC-IR)·발열 이상을 검증하는 에이징 · 종합 특성검사 · 단위 포장출하 3대 공정을 채택합니다.

Factory I/O 물리 한계 극복을 위한 HIL(Hardware-in-the-Loop) 모사 원칙

Factory I/O는 컨베이어·실린더·크레인 등 기계·물류 물리 엔진만 내장하고 있으며 전기 임피던스(AC-IR)나 전압 감쇠를 자체 연산하지 못합니다. 따라서 Project B는 ① 외부 Python/SCADA 가상 계측 엔진에서 검사 스테이션 RFID로 읽은 PACK ID별 ΔV, AC-IR(mΩ), 보관 온도(°C)를 연산해 판정 코드(D1700)를 생성하고, ② Factory I/O 3D 씬에서는 상단 Z축 프로브 하강 접촉 모션(1.5초 유지), 경광등 점등, 기계식 Sorter 분기 인터록을 PLC로 동일하게 제어하는 HIL 모사 아키텍처를 채택합니다.

실제 양산 현업 vs 데모 시뮬레이션 단순화(Scaling) 기준 명시
  • 적재 단위 단순화: 현업은 수십~수백 셀을 담은 트레이(Tray) 단위로 스태커에 입출고하나, Factory I/O 24칸 창고 규모에 맞춰 1 팩 = 1 랙 칸으로 축소 모사했습니다. 공작물은 4S(2×2) = Small box, 6S(2×3) = Large box입니다.
  • 팩 단자 2점 측정: 팩 검사는 Project C와 같은 단일 도킹(+/− 2점) 기준이라 ΔV·AC-IR은 팩 전체 값입니다. 셀별 값은 B에서 측정하지 않고, C가 공유 DB에 넣은 셀 이력(셀 ID · 슬롯 · 셀 전압)을 PACK ID로 조회합니다. 따라서 B 검사로는 어느 셀이 불량인지 가려낼 수 없으며, NG 팩은 NG 라인 배출로 프로젝트 범위가 끝납니다(셀별 확인은 범위 밖에서 사람이 한다는 가정).
  • 판정 기준: 18650 3.7V 셀 1개 기준(ΔV PASS ≤ 80mV / RETEST ≤ 150mV, IR PASS ≤ 2.5mΩ / RETEST ≤ 3.2mΩ)에 셀 수(4 또는 6)를 곱한 시연값입니다.
  • 시간 및 온도 환경 스케일링: 현업의 수일~2주 상온(25°C)·고온(45~60°C) 숙성 및 상온 냉각 안정화 공정은 시연 가능하도록 상온 에이징(25°C 기준) + 시간 배속(72h → 12s)으로 압축했습니다.
  • 물리 계측(HIL) 타협 범위: Factory I/O는 열·전기 물리가 없으므로, 랙 점유/잠금 상태(Rack_Lock)와 크레인 좌표 제어는 PLC에서 실제 수행하고 ΔV·AC-IR·보관 온도(Temp) 계측 및 발열 트리거(>38.0°C)는 Python/SCADA HIL 엔진에서 가상 연산합니다.
  • 열화 판정 수식 단순화: 현업은 시간당 전압 강하율(K-value = ΔV/Δt)을 추적하나, 본 시뮬레이션은 고정 숙성 완료 시점의 ΔV · AC-IR · Temp 3대 지표 AND 판정 모델로 단순화했습니다.
삼성SDI 표준 공정 적용 여부 Project B 디지털 트윈 구현 정의
1. 충방전 (Formation) 제외 베어 셀 화학 활성화(SEI·디게싱) 단계로, C에서 이미 셀 전압 측정과 4S 팩 조립·팩 전압 검사를 마치므로 중복 배제
2. 에이징 (Aging) STEP 02 24칸 AS/RS 자동창고 적재 후 랙별 개별 입고 Timestamp 기반 독립 타이머로 동시 숙성 및 온습도 추적
3. 특성검사 (Inspection) STEP 03 검사 스테이션 RFID로 PACK ID를 읽고, Python이 해당 ID의 ΔV, AC-IR, 최고온도를 생성해 AND 판정 (HIL 물리 계측 갠트리 Z-Probe · 접점 클램프 · IR 센서 동기화)
4. 출하 분류 (Sorting) STEP 04~05 박스 적재 없이 팩 1개 단위로 분류: PASS는 GOOD OUT, 불량은 원인과 관계없이 재검사 구역을 거쳐 2차 분리 ↓ NG 라인 하나로 반출하고 원인은 PACK ID별로 DB에 기록. 게이트 통과 수량은 D1900~D1903에 누적해 HMI에 표시

SECTION 02

현업 에이징(Aging) 창고 4대 병목 및 Project B 해결 아키텍처

INDUSTRIAL AGING OPTIMIZATION

현업에서 배터리 에이징은 수일에서 2주까지 소요되는 공정 최대의 시간 병목(WIP 적체) 구간입니다. 단순한 시뮬레이션 배속(72h→12s)을 넘어, 실제 양산 현장의 자동창고(Stocker)에서 발생하는 4가지 핵심 운영 문제를 PLC·SCADA 제어 로직으로 해결합니다.

BOTTLENECK 01 · 입·출고 경합 & 과숙성 만기순(EDD) 스케줄링

[현업 문제] 장기 에이징 중 신규 입고와 만기 출고 경합에 따른 과숙성·정체

현업은 다수의 스태커 크레인이 수주간 순환하지만, 입·출고 물량이 동시에 몰려 크레인 사이클이 밀리면 앞단 라인이 막히거나 숙성이 끝난 셀이 제때 못 나와 과숙성(Over-aging)됩니다.

▶ Project B 해결: 1크레인·24랙 축소 모델에서 랙별 입고 Timestamp를 추적해 숙성 만기 완료 순(EDD)으로 출고 우선권을 부여하고, 신규 입고와 출고가 교착되지 않도록 크레인·게이트 사이클을 제어합니다.
BOTTLENECK 02 · 이상 랙 보전 인터록 Rack Lockout & 수동 해제

[현업 문제] 발열·알람 발생 랙에 정상 셀 재적재 시 2차 불량·화재 위험

이상 발열(M1690)로 긴급 반출된 랙은 잔열·누액·설비 이상이 남아 있을 수 있어, 점검 전 다음 배터리가 배정되면 연쇄 불량이 발생합니다.

▶ Project B 해결: M1690 반출이 일어난 랙을 PLC Rack_Lock 비트로 즉시 사용 불가(LOCK) 봉쇄해 후속 입고품이 정상 빈 랙만 찾아 들어가도록 회피하며, 보전 점검 후 HMI 수동 해제 시 재가용합니다.
BOTTLENECK 03 · 에이징 중 열폭주 전이 M1690 긴급 반출 인터록

[현업 문제] 미세 내부 단락 셀의 보관 중 이상 발열·화재 확산

에이징 중 미세 내부 단락 셀이 상온 기준(25°C)을 크게 웃도는 이상 발열(38.0°C 초과)을 일으키면 인접 트레이·랙의 정상 배터리까지 연쇄 발화할 위험이 큽니다.

▶ Project B 해결: 랙 구역 온도 센서 감시 중 Temp > 38.0°C 감지 시 잔여 숙성 시간과 무관하게 M1690 긴급 반출 인터록을 발동해 출고면 크레인 B가 우선 인출합니다. 팩은 일반 팩과 같은 동쪽 출구로 나와 라인을 따라가다 1차 분리(Pop-up Wheel Sorter, M1661)에서 아래로 빠져 발열 격리 구역에 들어가고, PACK ID별로 DB에 ISO로 기록됩니다. 해당 랙은 LOCK합니다.
BOTTLENECK 04 · 합류부 정체 및 재검사 라인 포화 재검사 전용 검사기 (v4)

[현업 문제] 창고 출고 물량과 RETEST 복귀 물량의 검사기 합류 충돌

재검사 물량이 메인 라인으로 복귀할 때 단순 선입선출만 사용하면 합류부 교착(Merge Jam)과 재검사 라인 포화(메인 라인까지 줄이 밀림)로 전체 라인이 정지합니다.

▶ Project B 해결 (v4): RETEST 팩을 메인 검사기로 되돌리지 않고 재검사 라인(정치 없이 연속 이송) → 재검사 전용 검사기(RFID③ · OCV·IR·온도)로 보냅니다(v6에서 정치 버퍼 삭제). 검사기 앞 합류가 없어져 합류부 교착이 생기지 않고, 재검사 GOOD만 검사 뒤 메인 라인에 간격 센서(X1903)로 합류합니다. 재검사 라인이 분기점까지 차면(M1800) RETEST·NG 팩은 메인 검사기 출구에서 기다려, 메인 라인 위에 멈춰 서는 팩이 생기지 않습니다.
SECTION 03

실시간 공작물 물리 이동 애니메이션 파이프라인 시뮬레이터

24칸 구역 숙성 · M1690 긴급반출 · 재검사 전용 라인 시뮬레이션 (v4)

SECTION 04

Factory I/O 3대 종합 특성검사(ΔV · AC-IR · 최고온도) HIL 판정기

4종 물리 에셋 + 3대 지표 AND 판정 엔진

Python/SCADA 가상 계측 엔진에서 검사 스테이션 RFID로 읽은 PACK ID별 ΔV, AC-IR(mΩ), 보관 온도(°C)를 연산해 판정 코드를 생성하고, Factory I/O 3D 씬에서는 Z축 프로브 접촉 모션·경광등·분기 암으로 동기화합니다.

ASSET 01 · 정위치 고정

Roller Stop + Diffuse Sensor

에이징 창고에서 출고된 팔레트가 검사 지점에 도달하면 광전 센서가 감지하고 스토퍼가 상승해 정위치에 고정합니다.

ASSET 02 · 프로브 접촉 모션

Two-Axis Z축 / 상단 Pusher

PLC 검사 비트(M1700)가 켜지면 Z축 계측 프로브가 팔레트 단자 위까지 하강해 1.5초간 접촉 모션을 수행합니다.

보관 시간별 OCV 감쇠(ΔV) 곡선 및 5단계 공정 상세 명세

5-STAGE SPECIFICATION
보관 시간별 팩 OCV 자기방전 감쇠(ΔV) 시뮬레이션 모델 (4S 팩 초기 기준: 14.800V)
시나리오 버튼을 전환하여 에이징 경과 시간에 따른 전압 강하 추이와 판정 임계선을 비교합니다.

STEP 01. Infeed & RFID 등록

M1510 · D1510~1517 · RFID
  • Project C에서 팩 검사 OK 판정된 팩이 진입하면(4S = Factory I/O Small box, 6S = Large box) 입구 센서가 감지 후 스토퍼로 정지시키고, 비전 센서로 박스 크기를 읽어 공유 DB의 팩 종류(cell_count)와 대조합니다.
  • RFID 리더로 태그 시리얼을 읽고 미등록(index0 = 0)을 확인한 뒤, C에서 받은 PACK ID(하우징 ID)와 C가 측정한 팩 전압을 태그에 기록·검증합니다. 팩 종류는 태그 idx9(셀 수 4/6)에 쓰고, 셀(셀 ID · 슬롯 · 셀 전압)은 같은 PACK ID로 공유 DB에 들어와 있으므로 태그에는 넣지 않습니다.

STEP 02. 관통형 AS/RS 배속 에이징

M1600 · M1601 · D1600
  • 24칸(4단×6열) 랙의 한쪽 면에 입고 라인(크레인 A), 반대쪽 면에 출고 라인(크레인 B)을 둔 관통형 구조입니다. 같은 셀을 앞면으로 넣고 뒷면으로 꺼내므로 입·출고 크레인 사이클이 서로 간섭하지 않습니다.
  • 배속 타이머(72h → 12s)를 가동하며 보관 온습도(25.0°C) 및 시간별 자기방전(ΔV)을 추적합니다.

STEP 03. 메인 검사 · 재검사 (검사기 2대)

RFID② D1520~27 · RFID③ D1530~37 · D1700~44
  • 팩이 검사 스토퍼에 정지하면 검사 스테이션 RFID 리더(D1520~D1527)가 태그 idx0(PACK ID)·idx4(재검사 횟수)·idx9(셀 수)를 읽어 D1711·D1712·D1714에 쓰고 D1710=1로 계측을 요청합니다. OCV·IR·온도를 모두 잽니다.
  • Python 가상 계측 엔진이 그 PACK ID로 ΔV·AC-IR·온도를 난수 생성해 D1701~1703과 판정 D1700을 회신하고, 최종 판정을 PACK ID별로 DB(inspection.db)에 저장합니다. PLC는 판정·계측값을 태그 idx4~8에 다시 기록합니다.
  • 불량은 원인과 관계없이 NG 라인 하나로 배출합니다. 원인은 판정 코드 NG-ΔV(3)·NG-IR(4)·NG-TEMP(5)로 구분해 DB에 남깁니다(복수 불량 시 온도 → ΔV → AC-IR 우선).
  • 재검사 전용 검사기: RETEST 팩은 재검사 라인을 따라 쉬지 않고 바로 가서 RFID ③(D1530~D1537)으로 PACK ID를 읽고 같은 방식(OCV·IR·온도)으로 다시 잽니다. 요청은 별도 블록(D1740~D1744), 결과는 D1730~D1733이라 메인 검사기와 동시에 요청해도 충돌하지 않습니다.

STEP 04. 개별 분류 (1 EA 단위) & 재검사 라인

M1660 · M1661 · M1720 · M1731 · M1732 · M1800 · X1903
  • 개별 분류: 박스 적재 없이 팩 1개씩 D1700 판정에 따라 바로 분기합니다. PASS(1)는 직진해 GOOD OUT, RETEST(2)와 NG(3·4·5)는 모두 Sorter(M1720)로 남쪽 재검사 라인에 보냅니다. 메인 NG는 태그 idx5에 3·4·5가 남아 재검사기에서 계측 없이 통과합니다. 1차 분리(M1660 직진 / M1661 ↓ 격리)는 메인 검사기 앞에 있습니다.
  • 재검사 라인: 정치 없이 연속 이송(D1800 라인 위 팩 수) → 재검사기 → 2차 분리(Pop-up Wheel Sorter): GOOD은 위(M1731) → X1903으로 메인 라인 간격을 확인한 뒤 합류해 GOOD OUT, NG는 아래(M1732) → NG OUT. 재검사기가 사용 중이면 팩은 재검사기 앞에서 간격을 두고 줄을 서고, 줄이 M1720 분기점까지 차면(M1800) GOOD 외 판정 팩은 메인 검사기 출구에서 기다립니다. 그동안 크레인 B는 새 팩을 내보내지 않습니다. 재검사는 1회까지이며 태그 idx4로 관리합니다.

STEP 05. 출하·배출 게이트 카운터 & HMI 표시

X1900~1902 · D1900~1904 · M1920
  • 3개 게이트(GOOD OUT · NG · M1690 격리) 입구 센서(X1900~X1902)의 상승 엣지마다 정전 유지 카운터(D1900~D1902)를 1씩 누적하고, 합계(D1903)와 수율(D1904, 0.1% 단위)을 계산합니다. 재검사 GOOD·NG도 같은 게이트에서 셉니다.
  • HMI는 D1900~D1904로 게이트별 수량·수율을, DB 집계로 원인별 불량 수량(ΔV · AC-IR · 온도)을 표시합니다. 리셋 버튼(M1920)은 PLC 카운터만 초기화하고 DB 이력은 남깁니다.

M1920 HMI_CNT_RESET Bit HMI 리셋 버튼 → D1900~D1904 0 초기화 (교대/일 단위, DB 이력은 유지)

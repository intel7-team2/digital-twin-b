- `OUT` 코일은 디바이스마다 한 줄에만 있습니다(이중 코일 없음, 7장에서 검사). 여러 곳에서 켜고 끄는 비트는 `SET` · `RST`만 씁니다.

### 2-2. 명령어 목록 표기 (5장)

```
J13  LD= D#13 K20 | AND= D1713 K0  =>  MOV D1526 D1711 | MOV D1527 D1712 | MOV K1 D1710 | MOV K30 D#13
```

- 한 줄 = 래더 한 회로. 맨 앞은 회로 이름(블록 글자 + 번호)이고 입력하지 않습니다. 세미콜론(`;`) 뒤는 설명입니다.
- `=>` 왼쪽은 접점 명령(왼쪽부터 직렬), 오른쪽은 그 회로에 다는 출력 명령(위에서 아래로, 적힌 순서대로 실행)입니다. 한 회로 안의 출력 순서는 바꾸지 않습니다.
- `OR` · `OR=`는 **첫 접점 바로 아래에 병렬로 다는 접점 하나**로만 썼습니다. `ANB` · `ORB`는 쓰지 않았습니다.
- `LD=` · `AND<>` 같은 비교 접점은 `명령 값1 값2` 순서입니다(W2에서 `LD<> D1903 K0` 형식 통과).
- `D#100Z0`은 "`D#100`에서 인덱스 레지스터 `Z0`만큼 뒤" 번지입니다(랙 표 24칸). `D1610Z0`은 `D1610~D1633` 가운데 한 칸입니다.
- `SM400`(항상 ON) · `SM402`(첫 스캔) · `SM412`(1초 클록) · `Z0~Z3`(인덱스) · `N0`(마스터 컨트롤)은 CPU 시스템 디바이스라 1500~19FF 블록(D9) 대상이 아닙니다.

| ⑮ | **운전 시간 `D#01`** 이 32000초(약 8.9시간)에서 1로 돌아가면 그때 랙에 있던 팩의 EDD 순서 · 숙성 판단이 틀어집니다 | 시연은 짧아 영향 없음(논의사항 문서 4-8과 같은 판단) |
| ⑯ | **재기동:** 래치 범위를 정하지 않아(논의사항 문서 4-9) STOP → RUN 때 스텝 · 랙 표가 0이 됩니다. Factory I/O 씬에 팩이 남아 있으면 표와 어긋납니다 | 씬도 같이 리셋. 초기화 버튼은 13장 E1(보류)에 적힌 것과 같은 문제 |

### 6-2. 핸드셰이크 순서 대조 (`serve` · `plc_side_check.py`)

| 순서 | `serve`가 기대하는 것 | 이 설계 |
|---|---|---|
| 요청 | 요청 블록 +1 PACK ID · +2 재검사 · +4 셀 수를 쓰고 +0 = 1 | J12(셀 수) → J13(PACK ID · 재검사 · 요청 = 1) / N15 → N19. 완료(+3)가 0일 때만 요청 |
| 응답 | 결과 블록 4워드 기록 → DB 저장 → +3 = 1 | J16 · N22에서 +3 = 1을 기다림 |
| 태그 기록 · 요청 내림 | PLC가 값을 읽고 태그 `idx4~8` 기록 → +0 = 0 | J18~J28 → J29 / N24~N31 → N33 |
| 완료 내림 | 엔진이 +3 = 0 | 다음 요청 조건(J13 · N19의 완료 = 0)으로 확인 |
| 발열 격리 | `D1651` · `D1652` 쓰고 `D1650` = 1 → `D1653` = 1 → `D1650` = 0 → `D1653` = 0 | G01 → G05 → G06 |

`plc_side_check.py`는 PLC 쪽을 흉내 내 같은 번지에 직접 쓰므로, 이 래더가 도는 프로젝트에서는 래더와 겹치지 않게 운전 정지 상태에서 씁니다.
